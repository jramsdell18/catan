# Catan Multiplayer Starter

Browser-based multiplayer Catan-style game built with React, Three.js, and a UI-independent rules engine.

The current host-authoritative full-game experience is the MVP. See the **[`v1.0.0 production plan`](ROADMAP.md)** for the server-authoritative public-release roadmap, dependencies, release blockers, and deferred nice-to-haves. A UI overhaul (non-3D rendering becomes dev-only; all player-facing information moves into the 3D UI) is separate planned work with its own user-experience roadmap, not covered by that plan.

For a quick explanation of the tools, hosting, code areas, and how they connect, see **[`docs/architecture.md`](docs/architecture.md)**.

## Run locally

```bash
npm install
npm run dev
```

Open the local URL printed by Vite. The current screen lets you pick a player count, inspect a 3D board, and randomize the terrain layout.

## LiveKit voice and video

The game uses LiveKit for table voice/video. Once a player has a color, their circular camera feed appears over that seat's 3D rack (empty seats show no bubble). LiveKit marks active speakers, and the app shows those players with a green video border.

## Inviting friends (join flow)

1. **Host:** open the site. A fresh room link (`?room=catan-table-<random id>`) is created in the address bar and remembered in this tab as "your" room. Enter your name and select **Create lobby**. You start as Red and can tap another open color.
2. **Share:** in the lobby, select **Copy invite link** (the link is also shown so you can select it by hand). Anyone opening it is a guest in the same room.
3. **Guest:** open the link, enter a name, select **Continue**, then **pick one of the open colors**. Taken colors are greyed out with the owner's name. You join the game only after the host confirms your color; voice and camera start at that point.
4. **Races:** if two people pick the same color, the host's browser is the referee. It applies claims in the order they arrive, gives the color to the first one, and tells the other "Blue was just taken by … Pick another color."
5. **Full lobby:** if every color is taken, a guest sees a **Lobby is full** screen, is disconnected from the call, and is not added. They can **Try again** or **Start a new game**.
6. The host chooses 3 or 4 players and selects **Start game** once every color is filled.

Color claims are validated only by the host browser (`resolveSeatClaim` in `src/game/multiplayerRoom.js`) over the LiveKit data channel. That is fine for friendly games but is not a security boundary; the planned room service will take this over.

LiveKit tokens are generated by `netlify/functions/livekit-token.js`, because the API secret must stay server-side. Set these environment variables in Netlify:

```bash
LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
VITE_LIVEKIT_TOKEN_ENDPOINT=/.netlify/functions/livekit-token
```

For local video-call testing, run the app through Netlify Dev so the function endpoint is available. Plain `npm run dev` still runs the board, but the LiveKit join button needs a reachable token endpoint.

## Solo test with bots

To play alone (locally or on the deployed Netlify site), tap the small **gear** in the bottom-right corner. Either select **Start solo game** (after picking 3 or 4 players), or switch **Bots** on to get a solo setup card with a **Start game** button. You play Red; every other seat is a bot. The game runs entirely in your browser, so no table call is needed.

Bots are for testing only and have no strategy. After a short pause (about 0.5–1 second) a bot places its setup settlement and road on random legal spots, rolls on its turn, and ends its turn without building, offering trades, or playing cards. Bots do answer your trade offers: they accept when they can afford what you ask for and decline otherwise. When a 7 is rolled, bots discard random cards and move the robber to a random hex, robbing a random eligible player. Switch **Bots** off in the gear menu (or select **Play with friends instead** on the solo card) to leave solo mode.

## Board-first layout and trading

The 3D board fills the screen on phones and desktops, with as few controls as possible:

- **Top:** one line telling you what to do now ("Place your settlement: tap a glowing spot", "Roll the dice", "Build, trade, or end your turn", "Waiting for Blue (bot)…"). A small dice chip opens the last roll's details.
- **Bottom right:** exactly one highlighted primary action for the phase (**Roll dice**, **End turn**, or **Cancel** while placing a piece). Beside it, only actions that make sense now: **Build** (one button that expands to the builds you can afford, with costs for the rest), **Cards** (only when you have development cards or can buy one), and **Trade**. When it is not your turn, none of these are shown.
- **Bottom left:** slim chips with every player's public hand count and your resources.
- **Gear (bottom-right corner):** rare actions: bots/solo game, reset camera, restart game, rules link, and (dev builds only) developer tools.

Short toasts, colored by the acting player, announce actions for every client and for bots.

To trade, tap the swap icon, add cards you give (tap to add, minus to remove) and cards you want, then choose one or more players (or **All players**). Each recipient accepts or declines on their own screen; the first valid accept wins and you see every response. Bank and port trades are on the same sheet. Opponents' actual cards are never shown, only their public card counts.

## Test the rules integration

1. Run `npm install`, then `npm run dev`.
2. Open the gear menu and choose **Local test mode** (dev builds), pick 3 or 4 players, and select **Start game**.
3. Follow the highlighted intersections and edges to place each settlement and road. The rules engine enforces the distance rule, road adjacency, and the two-round snake order.
4. After setup, confirm the phase changes to `roll` and every player has one wood, brick, ore, hay, and sheep.
5. Select **Roll dice**. A normal production roll changes the phase to `action`; inspect the resource totals, then select **End Turn** and confirm the current player changes.

Continue through robber/discard, building, development-card, trading, scoring, and game-over workflows to exercise the complete rules integration.

## Scripts

- `npm run dev` starts the Vite dev server.
- `npm run build` creates a production build in `dist/`.
- `npm run preview` serves the production build locally.
- `npm run test:all` runs unit + board + Playwright e2e.
- `npm run test:ci` mirrors GitHub Actions (unit + board + build + e2e).

**Testing details** (suites, single-test commands, CI): see **[`tests/README.md`](tests/README.md)**.

## CI

GitHub Actions runs on **every pull request to `main`** and **every push to `main`** (see `.github/workflows/ci.yml`):

1. Unit tests (`npm test` + `npm run test:rules`)
2. Production build (`npm run build`)
3. Playwright e2e (`npm run test:e2e`)

**Before merging to main:** open a PR and wait for the CI checks to pass. Enable branch protection on `main` to require those checks if you want merges blocked when red.
